# 分支与合并

> 默认分支始终可部署。所有工作从它拉出短生命周期分支，经合并请求合回去，然后删除分支。

**何时阅读：** 创建或删除分支、开合并请求、发版、热修之前。提交说明见 [commits.md](./commits.md)。加载协议见仓库根目录 [AGENTS.md](../../AGENTS.md)。

本文件默认采用 [GitHub Flow](https://docs.github.com/en/get-started/using-github/github-flow)：一条主干、短分支、合并请求。不采用 Git Flow 那套长期 `develop` + 日常 `release` 矩阵。

## 1. 主干

- 唯一长期分支是仓库**默认分支**。本仓库用 `main`。
- 仓库若已是 `master` 或 `develop`，服从现状，不要并列两条主干。
- 主干受保护：禁止直接 push。CI 未通过或未经批准的请求不得合并。
- 合入主干的代码视为可部署。主干红灯时先修主干，再开新功能。

## 2. 日常流程

```
main ──► feat/42-preview ── 提交并推送（见 commits.md）
              │
              ▼
         打开合并请求，关联 Issue
              │
              ▼  CI 绿 + 评审通过
         合入 main，删除短分支
```

- **一件事一条分支。** 无关改动拆开，便于评审和回滚。
- **短分支：** 以天计，不以周计。做不完用功能开关藏起来，不要养长分支。
- 从最新主干拉出。合入前把主干同步进来，自行解决冲突。
- 合入后删除远程与本地短分支。历史留在合并请求里。

## 3. 分支命名

```text
<type>/<issue号>-<短描述>
```

| type | 用途 | 示例 |
| --- | --- | --- |
| `feat` | 新功能 | `feat/42-preview` |
| `fix` | 缺陷 | `fix/87-login` |
| `docs` | 只改文档 | `docs/12-agents` |
| `refactor` | 行为不变的结构变化 | `refactor/15-naming` |
| `test` | 只改测试 | `test/9-error-paths` |
| `chore` | 构建、依赖、杂务 | `chore/3-ci` |
| `hotfix` | 生产紧急修复 | `hotfix/101-token` |

- `type` 与 [commits.md](./commits.md) 的 type 对齐。
- `{issue号}` 是仓库 Issue 编号，**不含 `#`**。没有 Issue 就先开 Issue，再开分支。
- `{短描述}`：小写英文、短横线分隔、不含空格。
- 不要把版本号写进日常分支名。版本用 tag，见 §5。
- 不要创建名为 `sit` 的分支。

## 4. 合并请求

- 标题说清意图。正文写**为什么**，并关联 Issue（`Closes #42`）。
- CI 必须绿才能合。
- 至少一人评审；作者不能给自己的请求批准备案。Agent 只开请求，不合入受保护主干。
- 默认 **squash 合入**，让主干上一条记录对应一次意图。squash 说明仍须符合 [commits.md](./commits.md)。
- 评审看设计、行为、测试、命名；格式交给工具。编码细则见对应 spec。

## 5. 发版与热修

默认在主干上打 SemVer tag 发布：`v主.次.补`，例如 `v0.1.0`。

仅当必须**并行维护已发布的旧版本**时，才从该版本 tag 拉出 `release/x.y.z`：

- 该线上的修复从对应 `release` 拉 `hotfix/`，合回该 `release`，再**拣选**到主干。
- 禁止把整支主干合回旧 `release`。
- 新功能只进主干，不进旧 `release`。

未到第一次发布、也不维护多版本时，不要创建 `release/*`。

## 自查清单

- [ ] 短分支是从最新主干拉的吗？名字是 `type/issue-描述` 吗？
- [ ] 是否一件事一条分支，且没有把版本号写进分支名？
- [ ] 是否关联了仓库 Issue（无 `#` 在分支名里，有 `#` 在请求正文里）？
- [ ] 合并请求 CI 是否绿、是否有他人评审？有没有直推主干？
- [ ] 合入后短分支删了吗？squash 说明符合 commits.md 吗？
- [ ] 若动了 `release/*`：是否真的在维护旧版本，而不是空造发版矩阵？
